# Issue tracker

## Tracker

Issues for this repository are local Markdown files.

Create and maintain each issue under:

```text
.scratch/<feature>/
```

Use a descriptive feature directory and keep the issue, supporting notes, and implementation artifacts together.

## Workflow

1. Create a feature directory under `.scratch/`.
2. Create a Markdown issue file that describes the problem, expected outcome, acceptance criteria, and relevant context.
3. Update the issue as implementation decisions or scope change.
4. Treat the local issue file as the source of truth for work in progress.

## Pull requests

Pull requests are not part of the issue-tracker workflow by default.
